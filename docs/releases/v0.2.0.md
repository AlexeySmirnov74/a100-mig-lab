# v0.2.0 — Reproducible A100 MIG portfolio lab

This release turns the original A100 40GB experiment into a documented, reviewable portfolio project: English-first documentation with a Russian translation, an architecture diagram, five preserved screenshots, live badges, and an end-to-end reproduction procedure.

## Correctness and reliability

- Fixed per-request HTTP client creation and buffered streaming in the context guard. Native SSE is forwarded incrementally; disconnects close upstream connections and release in-flight gauges.
- Made context recovery a bounded, same-model retry with per-tier input/output limits. Supported instructions are retained within the budget; tool/multimodal requests are not silently rewritten.
- Added controlled 400/502/504 responses, restricted overflow detection, and preserved relevant upstream error headers.
- Removed global Docker-container stops during MIG configuration. All hardware discovery and UUID assignment are scoped to the selected GPU; replacing an existing layout requires `MIG_RESET=1`.
- Fixed inconsistent working directories, smoke-test failures, stale network assumptions and unsafe cleanup defaults.

## Observability and lower overhead

- Changed Prometheus/DCGM cadence to 15 seconds rather than scraping every 500ms.
- Corrected MIG profiling percentages, memory units, occupancy thresholds, missing-data handling and the Grafana datasource UID.
- Added authenticated LiteLLM scraping using a Compose secret.
- Reused HTTP connections in the proxy and traffic generator. These reduce avoidable software overhead; no GPU speedup percentage is claimed.

## Reproduction and presentation

- Pinned LiteLLM `1.108.5`, Open WebUI `v0.13.3`, and the default Qwen model revisions. TGI `3.3.1` is retained for continuity with the original experiment.
- Updated Python/framework dependencies, bound ports to loopback by default and moved persistent data to named volumes.
- Added GPU-free regression tests and CI checks for shell, Compose, Prometheus, dashboard JSON, SVG and local documentation references.
- Documented official NVIDIA/Hugging Face/LiteLLM recommendations and a protocol for future latency, throughput and OOM-isolation measurements.

## Validation and limitations

Release publication is gated by the [CI workflow](https://github.com/AlexeySmirnov74/mig-litellm-nvidia-a100-lab/actions/workflows/ci.yml). The guard has 17 offline regression tests; hardware automation is checked against mocked `nvidia-smi` and Docker responses.

**No A100 was available to validate this release on hardware.** The screenshots were preserved from the earlier experiment, not generated as new benchmark results. CUDA inference, model fit, the OOM-isolation scenario and performance must be rerun on an A100 40GB. TGI is now in maintenance mode; a future serving-engine migration requires its own GPU validation.

## Upgrade

Copy the new settings from `.env.example`, set fresh secrets, recreate/export MIG UUIDs where required, and run `bash scripts/05_start_stack.sh`, then `bash scripts/06_demo_queries.sh`.

Existing bind-mounted `state/` data is **not automatically migrated** into the new named volumes. Back it up and migrate deliberately if retaining an existing Open WebUI account or monitoring history. The default Compose project name is now `mig-lab`; stop an older deployment using its original Compose project name before upgrading to avoid fixed-container-name conflicts. Do not run two deployments against the same MIG instances.
